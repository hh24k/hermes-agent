Security: Pairing and Allowlists

The Gateway does not respond to strangers. Access is controlled by a DM pairing system and an allowlist. Only accounts you approve can send commands to your agent.

Scheduled Tasks: Hermes at 3am

Hermes has a built-in cron scheduler that runs jobs while you sleep. Each cron job is a natural-language task description — no code required.

1
Describe the task in plain English

"Every morning at 8am: fetch the latest news about AI, summarize the top 5 stories, and send them to my Telegram."

2
Gateway ticks the scheduler every 60 seconds

The gateway process checks the jobs file once per minute. When a job is due, it spawns a fresh AIAgent with the task description as the initial prompt.

3
Isolated session — no prior context

Each cron run starts fresh, with no memory of previous runs. This prevents context buildup and keeps each run independent and predictable.

4
Results delivered to any platform

The output can be sent to Telegram, Discord, email, or saved to a file. Configure the delivery target when you create the job.

What Children Cannot Do

Child agents are deliberately restricted. They cannot: call delegate_task again (no recursive nesting), use the clarify tool (no user interaction), write to shared memory, or send platform messages. This prevents runaway chains and side effects.

Where the Code Actually Runs

When the terminal tool executes a command, where does it run? That depends on which execution backend you configure.

💻

Local (default)

Commands run directly on your machine. Fastest, but the agent has access to your full filesystem.

🐳

Docker

Commands run inside a container. Isolated from your host. Useful when you want sandboxing for untrusted code.

🌐

SSH

Commands run on a remote server over SSH. Control a VPS or cloud VM from your local Hermes instance.

⚡

Modal / Vercel Sandbox

Commands run on serverless cloud infrastructure. Hibernates when idle, wakes on demand. Near-zero cost between sessions.
