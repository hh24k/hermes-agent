Meet the Cast

Six players, each with a specific role. Know who does what — and you can tell your AI assistant exactly where to make changes.

The Six Players

Hermes is not one program — it is a team of specialized components. Each has one job. Like a film crew, everyone knows their role and hands off to the next person at the right moment.

⌨️
CLI — cli.py

The face of Hermes. Renders the terminal UI, captures your keystrokes, streams the AI response back to your screen. Uses prompt_toolkit to draw the interface.

🤖
AIAgent — run_agent.py

The engine. Manages the conversation loop, sends prompts to the LLM, receives tool call requests, executes tools (in parallel when safe), and feeds results back. This is the 1,000+ line core of Hermes.

🔧
Tools — tools/

The hands. 40+ individual tools: terminal, web search, file read/write, browser automation, image generation, voice, and more. Each is a callable function with a description the LLM reads to know when to use it.

📡
Gateway — gateway/

The messaging bridge. Connects Hermes to Telegram, Discord, Slack, WhatsApp, Signal, and more. One running process serves all platforms simultaneously — your Telegram message and a CLI session can share the same agent.

🧠
Memory — agent/memory_manager.py

The long-term memory. Saves important context across sessions — who you are, your preferences, ongoing projects. Written to MEMORY.md and USER.md files in your Hermes home directory.

📜
Skills — skills/

The playbook. Skills are Markdown files that encode workflows — like saved recipes. Hermes can create new skills from experience and improve existing ones automatically.

Where Everything Lives

Each actor has its own home in the codebase. Here is the map:

hermes-agent/ Root of the project
cli.py Terminal UI — the face users see
run_agent.py AIAgent engine — the conversation loop and tool execution
hermes_state.py SQLite session database — stores conversation history with full-text search
tools/ 40+ callable tools (terminal, web, files, browser, vision...)
agent/ AI internals: memory, skills, providers, prompt building
gateway/ Messaging platform bridges (Telegram, Discord, Slack...)
cron/ Scheduled task engine — run jobs automatically on a timer
skills/ Built-in skill library organized by category
providers/ LLM provider adapters — the layer that makes model-switching seamless
🗺️
Why This Matters for Steering AI

When you tell an AI coding assistant to "add a new tool," you can now say "add it to tools/ and register it in toolsets.py" — precise instructions that skip ambiguity and save back-and-forth.
