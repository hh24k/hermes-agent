What is Hermes Agent?

Hermes is an AI agent you run in your terminal. You type plain-English instructions. It figures out what to do, calls the right tools, and gets it done — writing code, searching the web, managing files, sending Telegram messages, all without you having to think about the steps.

It was built by Nous Research and works with any LLM — OpenAI, Claude, local models, or anything in between. Think of Hermes as the operating system, and the LLM as the CPU you plug in.

The Loop Can Repeat

The LLM might call multiple tools in sequence — read a file, then search the web, then write another file — before giving you a final answer. Each tool call is one iteration. Hermes caps this at 90 iterations per conversation so it never runs forever.

How Hermes Knows When to Stop

Every conversation has an iteration budget — a counter that caps how many tool calls can happen. Here is the actual code that manages it, from run_agent.py:

CODE 

class IterationBudget:
    def __init__(self, max_total: int):
        self.max_total = max_total
        self._used = 0
        self._lock = threading.Lock()

    def consume(self) -> bool:
        with self._lock:
            if self._used >= self.max_total:
                return False
            self._used += 1
            return True
PLAIN ENGLISH

A class (a reusable blueprint) called IterationBudget.

When created, it receives a maximum number of allowed steps.

Tracks how many steps have been used so far (starts at 0).

Uses a lock to prevent two tools from updating the counter at the same time (thread safety).

The "consume" method is called before each tool use.

It checks: have we hit the limit yet?

If yes — return False (stop, no more tools).

If no — increment the counter and return True (proceed).

🔒
Why the Lock?

Hermes can run multiple tools at the same time (in parallel). The lock prevents two tools from both reading the counter as "5", incrementing it, and writing "6" — which would skip a count. This is called a race condition.

Meet the Cast

Six players, each with a specific role. Know who does what — and you can tell your AI assistant exactly where to make changes.

The Six Players

Hermes is not one program — it is a team of specialized components. Each has one job. Like a film crew, everyone knows their role and hands off to the next person at the right moment.

⌨️
CLI — cli.py

The face of Hermes. Renders the terminal UI, captures your keystrokes, streams the AI response back to your screen. Uses prompt_toolkit to draw the interface.

🤖
AIAgent — run_agent.py

The engine. Manages the conversation loop, sends prompts to the LLM, receives tool call requests, executes tools (in parallel when safe), and feeds results back. This is the 1,000+ line core of Hermes.

🔧
Tools — tools/

The hands. 40+ individual tools: terminal, web search, file read/write, browser automation, image generation, voice, and more. Each is a callable function with a description the LLM reads to know when to use it.

📡
Gateway — gateway/

The messaging bridge. Connects Hermes to Telegram, Discord, Slack, WhatsApp, Signal, and more. One running process serves all platforms simultaneously — your Telegram message and a CLI session can share the same agent.

🧠
Memory — agent/memory_manager.py

The long-term memory. Saves important context across sessions — who you are, your preferences, ongoing projects. Written to MEMORY.md and USER.md files in your Hermes home directory.

📜
Skills — skills/

The playbook. Skills are Markdown files that encode workflows — like saved recipes. Hermes can create new skills from experience and improve existing ones automatically.

How the AI Knows What Tools Exist

Before each conversation, the AIAgent compiles a list of available tools and sends it to the LLM as part of the prompt. Each tool is described by a schema — a structured spec the model reads to know when and how to call that tool.

Here is the actual tool list from toolsets.py — the core tools every Hermes session loads:

CODE 

# From toolsets.py — the core tool list
_HERMES_CORE_TOOLS = [
    # Web
    "web_search", "web_extract",
    # Terminal + process management
    "terminal", "process",
    # File manipulation
    "read_file", "write_file", "patch", "search_files",
    # Skills
    "skills_list", "skill_view", "skill_manage",
    # Planning and memory
    "todo", "memory",
]
PLAIN ENGLISH

A list of tool names that are loaded for every session.

web_search: search Google. web_extract: read a webpage.

terminal: run shell commands. process: manage background processes.

Four file tools: read, write, apply a diff (patch), and search inside files.

Three skills tools: list available skills, view one, create/edit/delete them.

Two meta tools: todo (task tracking) and memory (write to long-term memory).

Each name in this list maps to a Python function in tools/. That function is what actually runs when the LLM asks for it. The schema (the description + parameter spec) is defined right next to the function code.

Running Tools in Parallel

When the LLM asks for multiple tools at once — say, "search the web AND read this file" — Hermes can run them in parallel instead of waiting for each one to finish. But not all tools are safe to run simultaneously.

1
Read-only tools are always parallel-safe

web_search, read_file, vision_analyze, session_search — these only read data. Running them simultaneously is safe because they do not change anything.

2
File-writing tools are parallel-safe for different paths

write_file and patch can run in parallel if they target different files. Writing to the same file at the same time would corrupt it.

3
Interactive tools are never parallel

The "clarify" tool asks you a question. Running two of these at once would produce two prompts simultaneously — impossible to answer. It always runs alone.

4
Up to 8 workers run at once

Hermes uses a thread pool of up to 8 parallel workers. If the LLM requests 10 tools, the first 8 start immediately, and the remaining 2 queue up.

⚡
Why This Matters in Practice

If you ask Hermes to "research 5 companies," it can open 5 web searches at the same time instead of 5 in a row. A task that would take 30 seconds sequentially can finish in 8 seconds. Knowing this helps you write prompts that take advantage of parallelism.

The Learning Loop

Most AI tools forget everything when you close the window. Hermes remembers — and gets smarter with every session through skills, memory, and a background curator.

Skills: Saved Procedures

Imagine if every time you solved a hard problem, you wrote the solution steps in a notebook. Next time, you hand the notebook to your assistant before they start. That is exactly what skills do.

📝
Markdown files as procedures

Each skill is a .md file in ~/.hermes/skills/. You can read, edit, and create them in any text editor. They are plain text — no code required.

⚡
Invoked with a slash command

Type /deploy-app and the skill named "deploy-app" is loaded. The agent reads the procedure and follows it step by step for your specific project.

🤖
Auto-created after complex tasks

After a long, successful multi-step task, Hermes can create a skill automatically — turning your one-off solution into a reusable procedure for next time.

🌐
Shareable via Skills Hub

The Skills Hub at agentskills.io lets you publish your skills and install others. One command: hermes skills install <name>.

Memory: What Hermes Remembers About You

Every session, the MemoryManager injects relevant context into the system prompt — so Hermes knows who you are before you say a word.

MEMORY.md General facts: your tech stack, preferred languages, ongoing projects. Hermes adds entries here with the memory tool.
USER.md Your personal profile: communication style, timezone, long-term goals. Updated by the Honcho dialectic modeling system over many sessions.
SOUL.md The agent personality file. Want Hermes to be formal? Concise? Funny? Write it here. Loaded into every system prompt.
state.db An SQLite database storing full conversation history. Has FTS5 full-text search — so Hermes can search across all past sessions to recall what you discussed weeks ago.
🔍
FTS5: The Memory Search Engine

FTS5 is a full-text search engine built into SQLite. When Hermes calls the session_search tool, it searches every message you have ever sent or received — instantly — without needing an external service. Your history never leaves your machine.

The Curator: Background Skill Maintenance

After you use skills repeatedly, some become outdated or redundant. The Curator runs while you are idle and keeps the skill library healthy automatically.

Here is the timing configuration from the actual agent/curator.py:

CODE 

# From agent/curator.py
DEFAULT_INTERVAL_HOURS = 24 * 7  # 7 days
DEFAULT_MIN_IDLE_HOURS = 2
DEFAULT_STALE_AFTER_DAYS = 30
DEFAULT_ARCHIVE_AFTER_DAYS = 90
PLAIN ENGLISH

The Curator runs at most once per week (24 hours × 7 days).

It only runs when Hermes has been idle for at least 2 hours — never while you are actively using it.

Skills that have not been used in 30 days are marked "stale" (a gentle warning).

Skills unused for 90 days are archived — moved aside, not deleted. Recoverable anytime.

🛡️
Never Auto-Deletes

The Curator follows a strict rule: it only archives, never deletes. An archived skill can always be restored. This is a safety-first design — your work is never thrown away without a way to recover it.

Security: Pairing and Allowlists

The Gateway does not respond to strangers. Access is controlled by a DM pairing system and an allowlist. Only accounts you approve can send commands to your agent.

Scheduled Tasks: Hermes at 3am

Hermes has a built-in cron scheduler that runs jobs while you sleep. Each cron job is a natural-language task description — no code required.

1
Describe the task in plain English

"Every morning at 8am: fetch the latest news about AI, summarize the top 5 stories, and send them to my Telegram."

2
Gateway ticks the scheduler every 60 seconds

The gateway process checks the jobs file once per minute. When a job is due, it spawns a fresh AIAgent with the task description as the initial prompt.

3
Isolated session — no prior context

Each cron run starts fresh, with no memory of previous runs. This prevents context buildup and keeps each run independent and predictable.

4
Results delivered to any platform

The output can be sent to Telegram, Discord, email, or saved to a file. Configure the delivery target when you create the job.

What Children Cannot Do

Child agents are deliberately restricted. They cannot: call delegate_task again (no recursive nesting), use the clarify tool (no user interaction), write to shared memory, or send platform messages. This prevents runaway chains and side effects.

Where the Code Actually Runs

When the terminal tool executes a command, where does it run? That depends on which execution backend you configure.

💻

Local (default)

Commands run directly on your machine. Fastest, but the agent has access to your full filesystem.

🐳

Docker

Commands run inside a container. Isolated from your host. Useful when you want sandboxing for untrusted code.

🌐

SSH

Commands run on a remote server over SSH. Control a VPS or cloud VM from your local Hermes instance.

⚡

Modal / Vercel Sandbox

Commands run on serverless cloud infrastructure. Hibernates when idle, wakes on demand. Near-zero cost between sessions.
